## 2026-07-14 - Masking Sensitive Payment Card Data and CVV Input
**Vulnerability:** The checkout workflow displayed the full primary account number (PAN) in plaintext on the order review page and accepted the Card Verification Value (CVV) in an unmasked text field without length or input format constraints. This exposed sensitive financial PII to shoulder surfing, screenshots, session recordings, and violated PCI-DSS Requirement 3.3.
**Learning:** React form templates often scaffold text inputs for card fields (`cardNumber`, `cvv`) without setting `type="password"`, `inputProps={{ maxLength }}`, or displaying masked summaries. When moving card state between checkout wizard steps, display components might directly render raw card data unless explicitly sanitized or masked.
**Prevention:** Always mask PANs on display components showing only the last 4 digits (`•••• •••• •••• 1234`), set CVV input fields to `type="password"`, and enforce strict input constraints (`maxLength`, `numeric` pattern). Add unit tests asserting masking and password input types to prevent regression.
