## 2026-07-26 - Sensitive Payment Information Leakage in Checkout Review and Form
**Vulnerability:** The order checkout summary (`src/payment/Review.js`) was leaking full, unmasked credit card numbers to the user interface, violating PCI-DSS compliance and presenting a severe data exposure risk. Additionally, the CVV input field in the payment form was completely unmasked and lacked input formatting restrictions, which could lead to shoulder surfing or processing of invalid payloads.
**Learning:** The application was built on standard rapid prototyping patterns where components merely forward raw state properties without defensive rendering or sanitization filters. Without explicit security review gates, developers directly mapped user inputs into output tables for verification.
**Prevention:** Always mask primary account numbers (PAN) to show only the last 4 digits on all UI components unless explicitly justified by business requirements. CVV input fields must always use `type="password"` and enforce strict numeric formats and length limits directly at both the handler level and the input field.
